# Strata 集群管理 产品规划

## 1. 定位

把多台各自运行 Strata 的机器组成一个集群，对外提供**一个**兼容 OpenAI / Anthropic 的入口，并提供一个管理控制台用来：接入与维护节点、观察集群与每台机器的运行状况、追踪每个请求被分到了哪里以及为什么、管理客户端访问密钥、调整路由策略。

目标用户：自建推理集群的个人或小团队管理员（1～10 台机器，每台一次处理一个请求）。

## 2. 核心概念

| 概念 | 说明 |
|---|---|
| 节点 | 一台运行 Strata 的机器（地址 + 节点密钥）。有启用、排空、停用三种管理状态，以及在线、忙碌、离线等运行状态。 |
| 会话 | 客户端的一段连续对话。按“系统提示 + 第一条用户消息”识别，用于把后续请求送回缓存所在节点。 |
| 固定前缀 | 系统提示 + 工具列表。节点处理过的固定前缀会被 Strata 长期缓存，换节点时据此估算重读量。 |
| 访问密钥 | 客户端调用入口用的密钥，可建多个、分别命名、启停、统计用量；与管理员登录分开。 |
| 路由决策 | 每个请求分到哪个节点，以及原因（粘性、空闲、换机、排队等），全部记录可查。 |

## 3. 功能模块

### 3.1 总览

- 集群指标卡：在线节点 / 总数、正在生成、排队请求、集群当前总速度（tok/s）、今日请求数、今日输出 token、平均缓存命中率。
- 节点状态墙：每个节点一张卡片，显示运行状态胶囊（空闲 / 读取 / 生成 / 排队 / 离线）、当前请求进度、速度、显存与 GPU 负载迷你曲线。点击进入节点详情。
- 最近路由事件流：最近的请求分配（时间、节点、原因、会话），节点上下线、增删等事件。
- 吞吐趋势图：近 1 小时集群输出速度与请求数。

### 3.2 节点

- 节点列表（表格）：名称、地址、模型、引擎版本、运行状态、管理状态、权重、当前请求、今日请求、累计分配、最后心跳、操作。
- 添加节点：地址 + 节点密钥 + 名称（可选）+ 权重 + 标签；保存前“测试连接”，显示探测到的模型、上下文长度、GPU、版本。
- 编辑节点：改名称、密钥、权重、标签。
- 管理状态：
  - 启用：正常参与分配。
  - 排空：不再接新会话，已有会话的后续请求和进行中的请求照常完成（用于维护前平滑下线）。
  - 停用：完全不参与分配。
- 删除节点：二次确认；有进行中请求时提示。
- 节点详情（右侧抽屉或独立页）：
  - 实时状态：阶段、提示读取进度、生成进度、速度。
  - 硬件指标卡（同 Strata 监控页）：速度、GPU 负载、显存、GPU 温度、功耗、PCIe、CPU、内存，每项带近期曲线。
  - 上下文占用环形图、显存专家缓存。
  - 引擎配置摘要：模型、上下文、KV、专家槽位、会话缓存。
  - 该节点最近请求（来自 Strata 自身记录：提示、复用、输出、速度、命中率、耗时）。
  - 打开该节点自带网页（新窗口）。

### 3.3 请求

- 请求日志（持久化）：时间、访问密钥名、接口（OpenAI / Anthropic）、模型、会话、分到的节点、路由原因、估算 token、实际提示 / 输出 token（从响应 usage 取）、首字延迟、总耗时、状态（成功 / 失败 / 客户端断开）。
- 筛选：时间范围、节点、密钥、状态、路由原因；按会话查看一串请求。
- 请求详情抽屉：路由决策过程（各候选节点当时的状态与估算重读量）、请求头摘要、错误信息。
- 保留策略：默认保留 30 天，可在设置中修改。

### 3.4 会话

- 活跃会话表：会话标识（短哈希）、所在节点、首条消息摘要、请求次数、最近活跃时间、估算上下文大小。
- 操作：迁移到指定节点（下一次请求生效）、解除绑定、固定到节点（不再自动换机）。

### 3.5 访问密钥

- 列表：名称、密钥前后缀、创建时间、最近使用、今日 / 累计请求与 token、状态。
- 新建（自动生成或手填）、启停、删除、重命名；创建后仅显示一次完整密钥并可复制。
- 兼容旧配置里的单一 `api_key`：迁移为一个名为“默认”的密钥。

### 3.6 路由设置

- 分配策略：平均分配（默认）/ 按负载 / 随机 / 按权重。
- 会话粘性：开关；换机阈值（重读 token 上限，默认 20000）；固定前缀剔除开关。
- 健康检查：探测间隔、超时、连续失败几次判离线。
- 失败重试：连接失败时改发其他节点（开关）。
- 所有修改即时生效并写入配置。

### 3.7 系统设置

- 管理员密码修改；登录会话有效期。
- 入口监听端口（重启生效，页面提示）。
- 日志保留天数；手动清理。
- 外观：浅色 / 深色 / 跟随系统。

### 3.8 告警（第二期）

- 节点离线、恢复、排队过长、请求失败率升高时：控制台顶栏提示 + 可选 Webhook（企业微信 / 钉钉 / 飞书 / 通用 JSON）。

## 4. 界面设计

- **视觉沿用 Strata 网页那套设计语言**：Outfit 字体；主色翡翠绿 `#10b981`；背景 `#f9fafb`、卡片白底 20px 圆角与分层浅阴影、`#dee5ee` 描边；数值 900 粗体大字 + 灰色单位；状态胶囊（读取蓝、生成绿、排队橙、错误红、空闲灰）；SVG 迷你曲线与 270° 环形仪表；表格表头小号大写灰字；深色主题沿用 Strata 的深色色板。
- 布局：顶栏（品牌“Strata Cluster”、分段式标签：总览 / 节点 / 请求 / 会话 / 密钥 / 设置、右侧集群状态胶囊与主题切换）；内容区最大宽度约 1200px。
- 技术栈：React + Tailwind + shadcn/ui + Framer Motion；shadcn 主题变量映射到 Strata 色板。
- 交互：实时数据 2 秒刷新；操作结果用右下角提示；危险操作二次确认；详情用右侧抽屉。
- 文案中文，不展示多余的技术说明。

## 5. 后端设计

- 仍为单进程 Python（标准库 + sqlite3），无额外依赖，systemd 用户服务常驻。
- 后台健康检查线程：每 2 秒拉取各节点 `/status`，每 5 秒拉取 `/metrics`（硬件、历史曲线、最近请求），缓存供控制台读取；请求到达时用缓存状态 + 入口自身的在途计数做决策，不再每个请求现查。
- 存储：`config.json` 保存节点、密钥（哈希）、路由与系统设置；`data.db`（SQLite）保存请求日志、事件、按小时汇总统计。
- 管理接口统一在 `/api/admin/*`，需管理员登录（密码 → 会话令牌）；推理接口 `/v1/*` 用访问密钥。
- 响应 usage 抽取：非流式读 JSON；流式在转发时顺带解析最后的 usage 事件，不影响直通。

## 6. 分期

| 期 | 内容 |
|---|---|
| 第一期（已完成 2026-10-04） | Strata 风格界面框架与主题；总览；节点（列表、添加含测试连接、编辑、启用 / 排空 / 停用、删除、详情抽屉含硬件指标）；请求日志（持久化、筛选、详情）；访问密钥；路由设置；管理员登录；系统设置 |
| 第二期 | 会话管理（迁移、固定）；告警与 Webhook；按模型路由（节点跑不同模型时按 `model` 字段分配）；统计报表（按天 / 节点 / 密钥） |

## 7. 验收标准（第一期）

- 自动化测试覆盖路由规则、节点管理状态（排空 / 停用）、密钥鉴权、请求日志落库与 usage 抽取。
- 真机：两台节点在总览实时显示；经入口的 Claude Code 请求在请求日志中可见且 token 数与 Strata 自身记录一致；排空节点后新会话不再分到该节点。
- 浏览器检查浅色 / 深色两套主题各页面无错位、控制台无报错。
