# Strata Router（strata-router）需求说明

完整的产品规划与分期见 [产品规划.md](产品规划.md)。本文记录当前已实现的功能与使用方式。

## 入口

- 地址 `http://<主机>:8099`，接口与 Strata 相同（`/v1/messages`、`/v1/chat/completions`、`/v1/models` 等），客户端只需改地址；使用控制台“密钥”页里的访问密钥。
- 另支持 OpenAI Responses 接口 `/v1/responses`（节点本身不支持）：入口把请求转成 Chat Completions 发给节点，再把结果转回 Responses 格式，流式与非流式都支持，分配规则与日志同普通生成请求，请求记录里协议显示为“Responses”。
  - 请求：`instructions` 与 developer 消息转为 system 消息；`input` 中的消息、`function_call`、`function_call_output` 分别转为对话消息、assistant 的 tool_calls、tool 消息；`reasoning` 条目忽略。`max_output_tokens` → `max_tokens`；`reasoning.effort` → `reasoning_effort`（minimal 按 low、xhigh 按 high）；只转发 function 类型工具，`tool_choice` 相应转换；`text.format` 的 json_schema / json_object → `response_format`。
  - 结果：思考内容 → reasoning 条目（摘要文字）；回答 → message 条目；工具调用 → function_call 条目；输出到上限时状态为 incomplete。流式按官方事件顺序发出 created、in_progress、各条目的 added / delta / done 以及 completed（或 incomplete、failed）。
  - 不保存历史回复，带 `previous_response_id` 的请求返回 400，需要客户端每次发送完整对话。
- 控制台 `http://<主机>:8099/admin`，用管理员密码登录（与访问密钥分开）。首次启动生成的初始密码在 `initial-admin-password.txt`（仅本人可读），登录后请在“设置”中修改。

## 分配规则（生成请求）

1. 会话识别：以“系统提示 + 第一条用户消息”的指纹识别同一会话。
2. 会话粘性（可关）：已有会话优先回到上次的节点。
3. 原节点忙时：估算换到各空闲节点需重读的 token（请求体字节数 / 3；目标节点最近处理过相同的系统提示 + 工具列表时剔除这部分），最小值不超过“换节点阈值”（默认 20000）就换，否则在原节点排队。
4. 新会话：有空闲节点则在空闲节点中按策略选，否则在所有启用节点中按策略选。策略：平均分配（默认）/ 按负载 / 随机 / 按权重。
5. 管理状态：启用正常分配；排空不接新会话，已有会话照常；停用不参与分配。只剩排空节点时仍会用它们兜底。
6. 节点连接失败时自动改发其他节点（可关）。

## 控制台

- 总览：在线节点、集群速度、今日请求与输出（含近 1 小时曲线）、节点状态墙、近 1 小时输出吞吐、最近事件、最近请求。
- 节点：列表（状态、管理状态、模型 / GPU、当前请求进度、今日与累计请求、权重、心跳）；添加（测试连接显示模型、上下文、GPU、引擎版本）、编辑（名称、密钥、权重、标签）、启用 / 排空 / 停用、删除；详情抽屉（当前请求、速度 / GPU / 显存 / 温度 / 功耗 / CPU / 内存 / PCIe 指标与曲线、上下文占用、引擎配置、节点自身请求记录、经入口的路由记录）。
- 请求：按时间范围、节点、密钥、状态筛选与搜索，分页；详情含用量（提示、缓存命中、输出）、首字延迟、耗时、错误、路由决策快照（各节点当时状态与估算重读量）。
- 密钥：新建（自动生成或自定义，完整密钥只显示一次）、启停、重命名、删除，今日与累计用量。
- 设置：路由、健康检查、日志保留与登录有效期、入口端口（重启生效）、管理员密码；两列底部对齐。外观（浅色 / 深色 / 跟随系统）在顶栏切换。
- 界面沿用 Strata 网页的设计语言（Outfit 字体、翡翠绿主色、卡片与指标样式、状态胶囊、深色主题）。

## 接口

- 管理接口 `/api/admin/*`（需登录令牌）：`login`、`logout`、`me`、`overview`、`nodes`（GET / POST，`nodes/test`，`nodes/{id}` GET / PATCH / DELETE）、`requests`（列表与 `requests/{id}`）、`keys`（GET / POST，`keys/{id}` PATCH / DELETE）、`settings`（GET / PUT）、`password`、`logs/cleanup`。
- 旧的 `/router/status`、`/router/backends` 已移除，由上述接口取代。

## 数据

- `config.json`：节点（含节点密钥）、访问密钥（只存哈希）、管理员密码哈希、路由 / 健康检查 / 系统设置；权限 600，不入库。示例见 `config.example.json`；旧格式（顶层 `api_key`、`strategy`）启动时自动迁移。
- `data.db`（SQLite）：请求日志、事件、管理员登录会话；按保留天数每小时清理。

## 运行与测试

- systemd 用户服务（模板 `strata-router.service.example`；需 Python 3.9 及以上，系统自带 3.8 不兼容），开机自启、崩溃 3 秒后重启；日志 `journalctl --user -u strata-router -f`。
- 后端测试：`python3 -m unittest test_router -v`（27 个，模拟 Strata 节点）。
- 前端：`web/`（React + Tailwind + shadcn/ui + Framer Motion），`pnpm build` 输出到 `web/dist`，由入口在 `/admin` 提供。
